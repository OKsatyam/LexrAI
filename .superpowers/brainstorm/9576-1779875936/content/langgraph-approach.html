Phase 3: LangGraph Architecture

How agentic should the Improve pipeline be? Pick the approach that fits the viva and deadline.

A

Linear Pipeline Graph

START → run_tools (all 3 at once) → explain (LLM) → END

Wraps current flow in a StateGraph. Same logic, LangSmith tracing added. Minimal LangGraph concepts. Fast to build.

Pros

  • Done in half a day
  • Zero risk to deadline
  • LangSmith still works

Cons

  • Not truly agentic
  • Weak viva story
B

Parallel Tool Nodes

START → ruff_node | bandit_node | radon_node (parallel) → aggregate → explain (LLM) → END

Each static analysis tool is its own node. LangGraph fans them out and joins. One LLM call at the end. Good educational value — teaches parallel state, fan-out/join.

Pros

  • Clear node/edge story
  • Teaches real LangGraph patterns
  • Still 1 LLM call (safe rate limits)
  • 1–2 days of work

Cons

  • No iterative loop (less "agentic")
C

Agentic Loop (ReAct-style)

START → plan (LLM picks tools) → invoke_tool → decide (LLM: done?) → loop back or → explain → END

LLM decides which tools to run, sees results, decides if more analysis is needed. Bounded: max 4 iterations, 2s delay. True agentic loop — strongest viva story.

Pros

  • Real StateGraph with conditional edges
  • Best viva story
  • Matches context.md vision exactly

Cons

  • 3–5 LLM calls per run
  • More complex to debug
  • 2–3 days of work

My recommendation: B — teaches the core LangGraph concepts clearly, fits deadline, defensible in viva. Choose C if you want the full agentic story and have 2–3 days.
